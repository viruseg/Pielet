# Pielet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Production-ready ESM JavaScript-библиотека круговых меню (`pielet`) с чистой геометрией, pointer interaction и CSS-темой.

**Architecture:** Класс `Pielet` (public API + orchestration) использует чистые geometry-функции (без DOM), `InteractionController` (pointer events), `MenuRenderer`/`ContentRenderer` (DOM/CSS), `ActiveMenuRegistry` (module-level singleton, один активный runtime). Все решения о selection — математические, DOM используется только для отображения.

**Tech Stack:** Vite (library mode, ESM), Vitest + jsdom (unit/integration), Playwright (E2E), tsc из JSDoc (`.d.ts`), чистый JS, zero runtime deps.

## Global Constraints

- Чистый JavaScript; runtime-зависимостей нет. Единственный production-формат — ESM. Никаких UMD/CJS/IIFE.
- API: `new Pielet(config)`, `menu.config` (мутабелен, snapshot при `open`), `menu.open(x, y)` (только с координатами), `menu.close()`. Без `destroy()`, без anchor-системы.
- Одновременно открыто только одно меню (module-level registry).
- Geometry — чистые функции без DOM; hit-testing математический.
- Секторы: `arc/N` с учётом gap; gap px→угол через средний радиус; эффективный gap уменьшается пропорционально, если не помещается; пункты не исчезают.
- Tie-break на границе: выигрывает пункт, раньше стоящий в `items` (inclusive-границы, first match).
- `MIN_EDGE_REALLOCATION_ARC = Math.PI / 2` (90°). Центр меню не двигается.
- Координаты — CSS pixels. scroll (capture) / resize / visualViewport.resize → закрытие.
- Pipeline: select event → close → удаление DOM/listeners → `const action = item.action; action?.();`.
- `typeContent`: none (не selectable, без hover, без action), text, image, node (append, без клонирования).
- Запрещены: Canvas, SVG, innerHTML, MutationObserver. Rendering: position:fixed, clip-path polygon.
- Визуальное — CSS variables, тёмная тема, полная изоляция (namespace `.pielet`).
- Валидация конфига при создании и при каждом `open`; явные Error; центральный DEFAULT_CONFIG.
- Events: open/close/select через EventTarget, без данных.
- Порядок задач: TDD; коммиты в main.

## Task 4: calculateVisibleArc

```js
export const MIN_EDGE_REALLOCATION_ARC = Math.PI / 2;
export function calculateVisibleArc({ centerX, centerY, outerRadius, startAngle, viewportWidth, viewportHeight })
// → { startAngle, arc } в радианах; fallback: { startAngle: deg2rad(startAngle), arc: 2π }
```
Алгоритм: per-edge видимые интервалы (формулы из обсуждения):
- left (x≥0): cos θ ≥ −cx/R → k≤−1: [[0,2π]]; k≥1: []; иначе [[2π−acos(k), 2π],[0, acos(k)]]
- right (x≤w): cos θ ≤ m=(w−cx)/R → m≥1: [[0,2π]]; m≤−1: []; иначе [[acos(m), 2π−acos(m)]]
- top (y≥0): sin θ ≥ −cy/R → k≤−1: [[0,2π]]; k≥1: []; иначе [[asin(k), π−asin(k)]]
- bottom (y≤h): sin θ ≤ m=(h−cy)/R → m≥1: [[0,2π]]; m≤−1: []; иначе [[0, asin(m)],[π−asin(m), 2π]]
Пересечение всех (intersectIntervals, merge, clamp [0,2π]). Если единственный интервал ≈ [0,2π] → full config-startAngle. Wrap merge: если первый [0,x] и последний [y,2π] → кандидат {startAngle: y, arc: 2π−y+x}. Выбор: интервалы длиной ≥ MIN_EDGE_REALLOCATION_ARC, ближайший mid к startAngle (wrap-aware). Нет кандидатов → full.
Tests: полный круг в центре; смещение к левому краю (видимая дуга слева-сверху/снизу); правый/верхний/нижний; углы (~90°); центр вне viewport (под низом → дуга сверху); меню больше viewport → fallback; выбор ближайшего к startAngle; wrap-merge.
