# Pielet API

Референс публичного API. Все типы описаны JSDoc-ом в `src/types.js` и продублированы в `dist/*.d.ts`.

## Класс `Pielet`

`new Pielet(config)` — создаёт экземпляр кругового меню. Экземпляр реализует `EventTarget`.

- Конструктор не создаёт DOM и не вешает слушателей.
- Конфигурация валидируется: неверная конфигурация приводит к ошибке с префиксом `Pielet config error:`.

### `menu.open(x, y)`

Открывает меню с центром в точке `(x, y)` (clientX/clientY viewport, CSS-пиксели).

- Перед открытием конфигурация перевалидируется и фиксируется snapshot; изменения `menu.config` во время открытого меню не влияют на текущий runtime, но применяются при следующем `open()`.
- Если координаты не являются конечными числами — бросает `Error` (`Pielet: open(x, y) requires finite client coordinates`).
- Если уже открыто другое меню (любого экземпляра) — оно мгновенно закрывается; открытым остаётся только последнее.
- Если этот же экземпляр уже открыт — предыдущий runtime заменяется (без повторного `close`-события).
- Диспатчит событие `open` с `detail.rect` и `detail.menu`.

### `menu.close()`

Плавно закрывает меню (fade-out). No-op, если меню закрыто. После завершения:

- DOM меню полностью удалён,
- все глобальные слушатели удалены,
- `close`-событие диспатчится ровно один раз. Повторный `close()` событие не генерирует.

### `menu.config`

Живой объект конфигурации (см. ниже). Менять можно в любой момент; изменения вступают в силу со следующего `open()`.

### `Pielet.closeAll()`

Статический метод: закрывает открытое меню, не требуя ссылки на экземпляр. Плавно закрывает текущее активное меню (как `menu.close()`, со всеми его гарантиями — `close`-событие, удаление DOM и слушателей). No-op, если ни одно меню не открыто (и не диспатчит `close`). Полезен для глобальных обработчиков (клик мимо меню, `blur`, `Escape` и т.п.), когда ссылка на экземпляр недоступна.

### События

Все события — `CustomEvent`, диспатчатся на самом экземпляре. Все несут `detail.menu` — экземпляр меню, для которого событие вызвано. `open` несёт также `detail: { rect }`; `select` несёт `detail: { id }` — строковый id выбранного пункта:

| Событие | Когда |
| --- | --- |
| `open` | Меню смонтировано и готово к взаимодействию. `detail.rect` — DOMRect-совместимый bounding rect видимой части меню; `detail.menu` — экземпляр меню. |
| `close` | Меню закрыто и удалено из DOM. `detail.menu` — экземпляр меню. |
| `select` | Пользователь выбрал пункт. `detail.id` — строковый id пункта; `detail.menu` — экземпляр меню; `detail.coords` — координаты указателя в момент клика по пункту (`{ x, y }`, clientX/clientY). |

`detail.rect` — plain-объект с полями `x`, `y`, `width`, `height`, `left`, `top`, `right`, `bottom` в client-координатах (CSS-пиксели, как у `open(x, y)`). Это bounding box видимой части меню — кольцевого сектора по видимой дуге: при полном круге rect совпадает с квадратом меню `(centerX − outerRadius, centerY − outerRadius, size × size)`, при edge-reflow — охватывает только ту дугу, по которой распределены пункты.

Порядок при выборе пункта: `select` → `close` → вызов `action`. Момент вызова `action` гарантирует, что DOM меню и все слушатели уже удалены. `action` вызывается с тремя аргументами — `id` пункта, экземпляром меню, для которого он вызван, и координатами клика `{ x, y }`. Исключение — пункт с `keepOpen: true` в click-режиме: `select` → вызов `action`, меню остаётся открытым, `close` не диспатчится.

### Правила жизненного цикла

- Нет `destroy()`: экземпляр переиспользуется сколько угодно раз через `open()`/`close()`.
- Нет anchor-системы: Pielet не подписывается на события «под», не знает про контейнеры и не реагирует на DOM-мутации.
- Одновременно открыто не более одного меню на страницу (модульный реестр, см. architecture).

## Типы

### `PieletConfig`

```ts
{
  size?: number;                        // 240, > 0
  centerSize?: number;                  // 72, 0 < centerSize < size
  gap?: number;                         // 4, >= 0 — расстояние между пунктами по внешней и внутренней дуге; при одном пункте игнорируется
  startAngle?: number;                  // -90 (градусы); при одном пункте — угол, на котором центрируется контент (для -90 текст сверху)
  direction?: 'clockwise' | 'counterclockwise';
  interactionMode?: 'click' | 'hold'; // см. описание ниже
  button?: 'left' | 'middle' | 'right' | 'back' | 'forward'; // 'left', отслеживаемая кнопка
  closeDistance?: number;               // 48, >= 0
  fit?: 'circle' | 'square';            // 'circle', способ вписывания контента в сектор
  unifyText?: boolean;                  // false, выровнять шрифт text-пунктов (только fit 'square')
  submenuDelay?: number;                // 400, >= 0 — задержка hover-открытия сабменю (см. ниже)
  submenuIndicator?: 'arc' | 'chevron' | 'both'; // 'both' — индикация сабменю-пунктов (см. ниже)
  availableArc?: ArcPartName[];         // см. ниже — части дуги для показа пунктов
  items: PieletItem[];                  // непустой, обязателен
}
```

### `availableArc`

Ограничивает дугу, по которой распределяются пункты меню (по умолчанию — полный круг). Непустой массив имён частей дуги (screen-углы: `0°` = право, `90°` = низ, `180°` = лево, `270°` = верх):

- Половины: `'right'` `[270°, 90°]`, `'bottom'` `[0°, 180°]`, `'left'` `[90°, 270°]`, `'top'` `[180°, 360°]`
- Четверти: `'top-right'` `[270°, 360°]`, `'bottom-right'` `[0°, 90°]`, `'bottom-left'` `[90°, 180°]`, `'top-left'` `[180°, 270°]`

```js
const menu = new Pielet({
  availableArc: ['right'],          // только правая половина
  items: [{ typeContent: 'text', content: 'A' }]
});
```

Правила валидации:

- Все имена должны быть известны; массив непустой.
- Объединение частей должно образовывать **одну сплошную дугу** без разрывов. Пересечения (например `['top', 'right']`) — не ошибка; разрывные комбинации (например `['top-left', 'bottom-right']`) — `Pielet config error`. Полный круг (например `['right', 'left']`) равнозначен отсутствию ограничения.
- Дубликаты игнорируются.

Поведение: пункты распределяются по заданной дуге. У краёв viewport, если запрошенная дуга выходит за экран, она **сдвигается/отзеркаливается** в свободную часть экрана (правая половина у правого края → пункты уезжают в левую половину), а если свободного места не хватает даже для неё — **сужается** до наибольшей непрерывной видимой дуги. Если видимая дуга меньше четверти круга (вырожденный случай, центр почти за экраном) — используется геометрия полного круга, как в обычном edge-reflow.

### `PieletItem`

```ts
{
  typeContent: 'text' | 'image' | 'node' | 'none';
  content?: string | Node;   // требуется для text/image/node
  id?: string;               // непустая строка; если не указан — генерируется
  action?: (id: string, menu: Pielet, coords: { x: number, y: number }) => void;
  keepOpen?: boolean;        // true — не закрывать меню при выборе пункта (только click-режим)
  isSubMenu?: boolean;       // true — открывать сабменю (menu) вместо action
  menu?: Pielet;             // экземпляр меню-сабменю; обязателен при isSubMenu: true
}
```

- `id` — опциональный идентификатор. Если не указан (или начинается с зарезервированного префикса `pielet-`) — генерируется при каждой нормализации (конструктор и каждый `open()`) в формате `pielet-<время>-<n>`, где `n` — счётчик, растущий на протяжении жизни страницы. Этот id передаётся в событие `select` (`event.detail.id`) и первым аргументом в `action` (вторым аргументом `action` получает экземпляр меню, третьим — координаты клика `{ x, y }`).
- `keepOpen` — если `true`, выбор пункта в click-режиме не закрывает меню: `select`-событие и `action` вызываются как обычно, но меню остаётся открытым для повторных кликов. В hold-режиме флаг не действует — меню закрывается по-прежнему. Клик по пункту без флага (а также по центру, зазору, `none` или за `closeDistance`) закрывает меню.
- `isSubMenu` — если `true`, пункт открывает сабменю (`menu`) вместо вызова `action` (см. «Сабменю» ниже). Требует `typeContent` не `'none'` и наличие `menu`. `select`-событие при клике по сабменю-пункту по-прежнему эмитится.
- `'text'` — текст, автоматически подгоняется под область сектора (fit-to-box).
- `'image'` — URL изображения.
- `'node'` — любой `Node` (иконка SVG, канвас и т.п.).
- `'none'` — пустой сектор: не hover, не select, `content` игнорируется. Используется как разделитель.

### `fit`

Определяет, как контент вписывается в сектор:

- `'circle'` (по умолчанию) — по безопасной окружности, вписанной в сектор (метод `safeRadius = min(r1, r2)`). Контент занимает вписанный в эту окружность квадрат и **не поворачивается** — текст всегда горизонтален.
- `'square'` — по прямоугольному боксу сектора (хорда × ширина кольца). Контент **поворачивается вместе с сектором** (`rotate(mid)`): левый край ложится к внутреннему радиусу меню, правый — к внешнему. Внутренний край бокса отстоит от внутренней дуги на `0.075 × ширина кольца` (симметричный отступ), внешний край — на 10px от внешней дуги; ширина бокса = ширина кольца минус эти отступы (вдоль радиуса), высота = 0.85 × длина хорды на среднем радиусе (вдоль дуги). Бокс смещён наружу — текст заполняет кольцо до внешнего края, а не центрируется с равными отступами с обеих сторон. В секторах левой половины круга (ось смотрит влево) контент дополнительно разворачивается на 180°, чтобы текст не был «кверху ногами» и читался от внешнего края к внутреннему.

Во всех режимах text-контент растягивается так, чтобы заполнить доступную область (шрифт подбирается максимальным, влезающим в бокс).

### `unifyText`

Булев флаг, действует только при `fit: 'square'` (в `'circle'` игнорируется). При `true` все `text`-пункты получают единый размер шрифта, равный наименьшему влезающему размеру среди них (шрифт пункта с самым длинным текстом). Выравнивание повторяется при `setItemContent`.

### `ContentType`, `Direction`, `InteractionMode`

Узкие строчные типы из `src/types.js` для JSDoc и d.ts.

## Ошибки

| Условие | Ошибка |
| --- | --- |
| Невалидная конфигурация | `Pielet config error: <причина>` |
| Нефинитные координаты `open()` | `Pielet: open(x, y) requires finite client coordinates` |
| Исключение в `action` | Пробрасывается наружу (не подавляется); меню остаётся закрытым. |

## Выбор сектора

- Секторы инклюзивны по границам: при попадании точно на границу выигрывает пункт, раньше стоящий в массиве `items`.
- Клик по центру, зазору или пустому сектору меню закрывает без `select`.
- Выход указателя за `outerRadius + closeDistance` закрывает меню без `select`.
- `contextmenu` предотвращается, пока меню открыто.

### Режимы взаимодействия

`'click'` (по умолчанию): меню остаётся открытым после клика, которым его открыли; последующий клик по сектору — выбор, клик вне пункта меню (центр, зазор, `none`, за `closeDistance`) — закрытие. Отпускание кнопки в течение grace-окна (300 мс после `open`) — это часть открывающего клика и меню не закрывает.

`'hold'`: меню живёт, пока кнопка (`button`) удерживается; отпускание на секторе выбирает, отпускание вне сектора закрывает. В hold-режиме меню также закрывается, если при движении указателя отслеживаемая кнопка не удержана (в т.ч. когда сабменю открыто кнопкой, не совпадающей с его `button`).

### Сабменю

Пункт с `isSubMenu: true` ссылается на другое меню (`menu`) и открывает его вместо вызова `action`:

```js
const colors = new Pielet({
  items: [
    { typeContent: 'text', content: 'Красный', action: () => setColor('#f00') },
    { typeContent: 'text', content: 'Синий', action: () => setColor('#00f') }
  ]
});
const menu = new Pielet({
  items: [
    { typeContent: 'text', content: 'Цвет', isSubMenu: true, menu: colors },
    { typeContent: 'text', content: 'Сброс', action: () => setColor(null) }
  ]
});
```

- **click-пайплайн**: клик по сабменю-пункту → `select`-событие (`detail.id` — id пункта) → закрытие родителя → `menu.open(x, y)` в точке клика. `action` игнорируется.
- **hold-пайплайн**: наведение на сабменю-пункт в течение `submenuDelay` мс (по умолчанию 400) → `menu.open(x, y)` в точке указателя. `select` и `action` не эмитятся — только открытие. Задержка действует в hold-режиме и в click-режиме, пока отслеживаемая кнопка удержана (click-меню ведёт себя как hold). `submenuDelay: 0` отключает hover-открытие.
- Если сабменю тоже в hold-режиме с той же кнопкой — оно подхватывает зажатую кнопку и работает как обычное hold-меню (наведение, выбор по отпусканию). Если кнопки меню и сабменю не совпадают — сабменю закроется при первом движении указателя (кнопка не удержана), что считается ответственностью пользователя.

### `submenuIndicator`

Сабменю-пункты автоматически помечаются индикатором (варианта «без индикации» нет):

- `'arc'` — акцентная дуга вдоль внутреннего радиуса сектора (у «основания» куска пирога). SVG-полилиния по `innerStart`/`innerEnd` сектора, не залезает в gap и не обрезается `clip-path`.
- `'chevron'` — стрелка на внешнем крае кольца, направленная радиально наружу (по средней линии `mid`). Рисуется SVG-глифом (не текстом `›` — у текстового глифа метрики шрифта смещают визуальный центр, и парные шевроны на `mid=0`/`mid=π` визуально уходят с общей линии). Размер бокса масштабируется с шириной кольца: `min(14px, ringWidth × 0.18)` — при стандартном меню 240/72 это 14px, в узких кольцах (например 120/24) шеврон уменьшается пропорционально. Центр шеврона — за внешним краем кольца (`outerRadius + size × 0.5` по `mid`): шеврон целиком сидит на внешней стороне кольца (внутренняя кромка бокса совпадает с внешним радиусом, внешняя торчит на `size`) и остаётся радиально дальше контента — не сливается с ним при любом `size` и `fit`. Элемент крепится к корню меню, а не к сектору — clip-path сектора срезает всё, что за кольцом.
- `'both'` (по умолчанию) — дуга и стрелка вместе.

DOM: у пункта добавляется класс `pielet__item--submenu`; дуга — `.pielet__submenu-arc` (svg+path) внутри сектора, стрелка — `.pielet__submenu-chevron` (svg+path, глиф симметричен относительно центра бокса) на корне меню (на внешнем крае кольца). Оба с `aria-hidden="true"` и `pointer-events: none`. Контент и `fitText` не затрагиваются. Цвет настраивается CSS-переменной `--pielet-submenu-indicator`.

### `button` (отслеживаемая кнопка)

И в hold-, и в click-режиме меню реагирует только на отпускание кнопки, заданной в `config.button` (текстовая константа, дефолт `'left'`): `'left'` → 0, `'middle'` → 1, `'right'` → 2, `'back'` → 3, `'forward'` → 4 (числовые коды соответствуют `PointerEvent.button`). Отпускание любой другой кнопки игнорируется — пункт не выбирается и меню не закрывается.

Сопоставление доступно как `Pielet.BUTTONS` (`{ left: 0, middle: 1, right: 2, back: 3, forward: 4 }`). Оно нужно вызывающему коду, чтобы открывать меню той же кнопкой, например:

```js
document.addEventListener('pointerdown', (e) => {
  if (e.button !== Pielet.BUTTONS[menu.config.button]) return;
  menu.open(e.clientX, e.clientY);
});
```
