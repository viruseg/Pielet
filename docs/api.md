# Pielet API

Референс публичного API. Все типы описаны JSDoc-ом в `src/types.js` и продублированы в `dist/*.d.ts`.

## Класс `Pielet`

`new Pielet(config)` — создаёт экземпляр кругового меню. Экземпляр реализует `EventTarget`.

- Конструктор не создаёт DOM и не вешает слушателей.
- Конфигурация валидируется: неверная конфигурация приводит к ошибке с префиксом `Pielet config error:`.

### `menu.open(x, y)`

Открывает меню с центром в точке `(x, y)` (clientX/clientY viewport, CSS-пиксели).

- Перед открытием конфигурация перевалидируется и фиксируется snapshot; изменения `menu.config` во время открытого меню не влияют на текущий runtime, но применяются при следующем `open()`.
- Если координаты не являются конечными числами — бросает `Error` (`Pielet: open(x, y) requires finite client coordinates`).
- Если уже открыто другое меню (любого экземпляра) — оно мгновенно закрывается; открытым остаётся только последнее.
- Если этот же экземпляр уже открыт — предыдущий runtime заменяется (без повторного `close`-события).
- Диспатчит событие `open` с `detail.rect` и `detail.menu`.

### `menu.close()`

Плавно закрывает меню (fade-out). No-op, если меню закрыто. После завершения:

- DOM меню полностью удалён,
- все глобальные слушатели удалены,
- `close`-событие диспатчится ровно один раз. Повторный `close()` событие не генерирует.

### `menu.config`

Живой объект конфигурации (см. ниже). Менять можно в любой момент; изменения вступают в силу со следующего `open()`.

### `Pielet.closeAll()`

Статический метод: закрывает открытое меню, не требуя ссылки на экземпляр. Плавно закрывает текущее активное меню (как `menu.close()`, со всеми его гарантиями — `close`-событие, удаление DOM и слушателей). No-op, если ни одно меню не открыто (и не диспатчит `close`). Полезен для глобальных обработчиков (клик мимо меню, `blur`, `Escape` и т.п.), когда ссылка на экземпляр недоступна.

### События

Все события — `CustomEvent`, диспатчатся на самом экземпляре. Все несут `detail.menu` — экземпляр меню, для которого событие вызвано. `open` несёт также `detail: { rect }`; `select` несёт `detail: { id }` — строковый id выбранного пункта:

| Событие | Когда |
| --- | --- |
| `open` | Меню смонтировано и готово к взаимодействию. `detail.rect` — DOMRect-совместимый bounding rect видимой части меню; `detail.menu` — экземпляр меню. |
| `close` | Меню закрыто и удалено из DOM. `detail.menu` — экземпляр меню. |
| `select` | Пользователь выбрал пункт. `detail.id` — строковый id пункта; `detail.menu` — экземпляр меню. |

`detail.rect` — plain-объект с полями `x`, `y`, `width`, `height`, `left`, `top`, `right`, `bottom` в client-координатах (CSS-пиксели, как у `open(x, y)`). Это bounding box видимой части меню — кольцевого сектора по видимой дуге: при полном круге rect совпадает с квадратом меню `(centerX − outerRadius, centerY − outerRadius, size × size)`, при edge-reflow — охватывает только ту дугу, по которой распределены пункты.

Порядок при выборе пункта: `select` → `close` → вызов `action`. Момент вызова `action` гарантирует, что DOM меню и все слушатели уже удалены. `action` вызывается с двумя аргументами — `id` пункта и экземпляром меню, для которого он вызван. Исключение — пункт с `keepOpen: true` в click-режиме: `select` → вызов `action`, меню остаётся открытым, `close` не диспатчится.

### Правила жизненного цикла

- Нет `destroy()`: экземпляр переиспользуется сколько угодно раз через `open()`/`close()`.
- Нет anchor-системы: Pielet не подписывается на события «под», не знает про контейнеры и не реагирует на DOM-мутации.
- Одновременно открыто не более одного меню на страницу (модульный реестр, см. architecture).

## Типы

### `PieletConfig`

```ts
{
  size?: number;                        // 240, > 0
  centerSize?: number;                  // 72, 0 < centerSize < size
  gap?: number;                         // 4, >= 0 — расстояние между пунктами по внешней и внутренней дуге; при одном пункте игнорируется
  startAngle?: number;                  // -90 (градусы); при одном пункте — угол, на котором центрируется контент (для -90 текст сверху)
  direction?: 'clockwise' | 'counterclockwise';
  interactionMode?: 'click' | 'hold'; // см. описание ниже
  button?: 'left' | 'middle' | 'right' | 'back' | 'forward'; // 'left', отслеживаемая кнопка
  closeDistance?: number;               // 48, >= 0
  items: PieletItem[];                  // непустой, обязателен
}
```

### `PieletItem`

```ts
{
  typeContent: 'text' | 'image' | 'node' | 'none';
  content?: string | Node;   // требуется для text/image/node
  id?: string;               // непустая строка; если не указан — генерируется
  action?: (id: string, menu: Pielet) => void;
  keepOpen?: boolean;        // true — не закрывать меню при выборе пункта (только click-режим)
}
```

- `id` — опциональный идентификатор. Если не указан (или начинается с зарезервированного префикса `pielet-`) — генерируется при каждой нормализации (конструктор и каждый `open()`) в формате `pielet-<время>-<n>`, где `n` — счётчик, растущий на протяжении жизни страницы. Этот id передаётся в событие `select` (`event.detail.id`) и первым аргументом в `action` (вторым аргументом `action` получает экземпляр меню).
- `keepOpen` — если `true`, выбор пункта в click-режиме не закрывает меню: `select`-событие и `action` вызываются как обычно, но меню остаётся открытым для повторных кликов. В hold-режиме флаг не действует — меню закрывается по-прежнему. Клик по пункту без флага (а также по центру, зазору, `none` или за `closeDistance`) закрывает меню.
- `'text'` — текст, автоматически подгоняется под область сектора (fit-to-box).
- `'image'` — URL изображения.
- `'node'` — любой `Node` (иконка SVG, канвас и т.п.).
- `'none'` — пустой сектор: не hover, не select, `content` игнорируется. Используется как разделитель.

### `ContentType`, `Direction`, `InteractionMode`

Узкие строчные типы из `src/types.js` для JSDoc и d.ts.

## Ошибки

| Условие | Ошибка |
| --- | --- |
| Невалидная конфигурация | `Pielet config error: <причина>` |
| Нефинитные координаты `open()` | `Pielet: open(x, y) requires finite client coordinates` |
| Исключение в `action` | Пробрасывается наружу (не подавляется); меню остаётся закрытым. |

## Выбор сектора

- Секторы инклюзивны по границам: при попадании точно на границу выигрывает пункт, раньше стоящий в массиве `items`.
- Клик по центру, зазору или пустому сектору меню закрывает без `select`.
- Выход указателя за `outerRadius + closeDistance` закрывает меню без `select`.
- `contextmenu` предотвращается, пока меню открыто.

### Режимы взаимодействия

`'click'` (по умолчанию): меню остаётся открытым после клика, которым его открыли; последующий клик по сектору — выбор, клик вне пункта меню (центр, зазор, `none`, за `closeDistance`) — закрытие. Отпускание кнопки в течение grace-окна (300 мс после `open`) — это часть открывающего клика и меню не закрывает.

`'hold'`: меню живёт, пока кнопка (`button`) удерживается; отпускание на секторе выбирает, отпускание вне сектора закрывает.

### `button` (отслеживаемая кнопка)

И в hold-, и в click-режиме меню реагирует только на отпускание кнопки, заданной в `config.button` (текстовая константа, дефолт `'left'`): `'left'` → 0, `'middle'` → 1, `'right'` → 2, `'back'` → 3, `'forward'` → 4 (числовые коды соответствуют `PointerEvent.button`). Отпускание любой другой кнопки игнорируется — пункт не выбирается и меню не закрывается.

Сопоставление доступно как `Pielet.BUTTONS` (`{ left: 0, middle: 1, right: 2, back: 3, forward: 4 }`). Оно нужно вызывающему коду, чтобы открывать меню той же кнопкой, например:

```js
document.addEventListener('pointerdown', (e) => {
  if (e.button !== Pielet.BUTTONS[menu.config.button]) return;
  menu.open(e.clientX, e.clientY);
});
```
